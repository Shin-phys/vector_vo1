# ベクトル作図ステップ学習（物理基礎）

高校「物理基礎」の授業で使う、ベクトルの作図とその意味を段階的に学ぶ Web アプリです。
ビルド不要。静的ファイルをそのまま配信すれば動きます（ES モジュールを使うので
`file://` ではなく HTTP で開いてください）。

## 2つのアプリ

| ファイル | 内容 | 時間 |
|---|---|---|
| `index.html` | **第1弾：運動の表し方**（位置・変位・つなぎ・速度・合成） | 1コマ |
| `relative.html` | **第2弾：相対速度**（基準の乗り換え） | 15分 |

見た目・色の規約・操作感は共通です。生徒が「別のアプリ」と感じないよう、
共通部品は `js/core/` に置いて両方から使っています。

    │   ├─ canvas.js           方眼の描画と座標変換（GridCanvas / WorldCanvas）
    │   ├─ vector.js           矢印の生成・ドラッグ・スナップ・判定・シーン
    │   ├─ bridge.js           図と式を並べ、タップで連動させる画面

## 第2弾の設計で崩してはいけないところ

1. **`camera.js` の分離**
   `world.js` は「本当の運動」だけを持ちます。どの基準から見るかは `camera.js`
   だけが知っていて、`view.js` は world と camera を受け取って描くだけです。
   **観測者系のために別の world を作らないでください。**

2. **`gridOffset` による背景の追随**
   観測者系では `gridOffset = −(観測者の位置)` となり、方眼・道路のセンターライン・
   樹木・標識がすべて一緒に流れます。これがないと「球だけが違う速さで動く映像」に
   なってしまい、視点の乗り換えが伝わりません。

3. **シーン1の「描くまで再生できない」制約**
   予測を描くまで再生ボタンはグレーアウトします。ここを飛ばすと、このアプリは
   ただの綺麗な映像になります。

4. **シーン4の記号への橋渡し**
   矢印と式をタップで連動させ、最後に数値で解かせます。見て終わりにしないための
   シーンです。

`anchor`（観測者の出発点に原点を置く）も設計上の要です。これにより t=0 では
二画面が完全に一致し、時間が進むにつれて差が現れます。

## 授業での調整

### シーンを飛ばす
`js/relative/main.js` の `SCENE_PLAN` の該当行をコメントアウトします。
第1弾は `js/main.js` の `STEP_ORDER` が同じ役割です。

### 直線（1d）と平面（2d）の切り替え
教科書によって相対速度を直線上だけで扱う場合と平面まで扱う場合があります。

```js
// data/config.js
export const relativeConfig = { dimension: '1d' };  // "1d" | "2d"
```

既定は `1d`（道路を2台が走る横からの図）です。`2d` にすると俯瞰の図
（斜めに交差する2物体・川を渡る舟）に切り替わります。問題データは
`data/problems-relative.js` に両方そろえてあります。
授業中に切り替えたいときは、画面右上の⚙からも変更できます（最初からやり直しになります）。

### 速さや配置を変える
`data/problems-relative.js` の `bodies[].vel` は **方眼のマス／秒** です。
表示される速さは `|v| × unitScale`（既定 10）で `m/s`。
`duration` を変えるときは、物体と矢印の先端が画面からはみ出さないか確認してください。

## 記号への橋渡し

このアプリの背骨は、**同じ1つのルール**です。

> **添字は「基準 → 対象」の順に書く。式は「対象 − 基準」（＝ 後 − 前）。**

| | 添字 | 式 | 読み |
|---|---|---|---|
| 変位（第1弾⑥） | 駅 → 公園 | r<sub>公園</sub> − r<sub>駅</sub> | 駅を基準にすると、公園はどこか |
| 相対速度（第2弾シーン4） | A → B | v<sub>B</sub> − v<sub>A</sub> | Aを基準にすると、Bはどう動くか |

矢印は **前→後**、式は **後 − 前**。ここが逆になるのが最大のつまずきどころなので、
**矢印の向きと式の並び順を同時にハイライトする**画面を、両方の教材に置いています。

記号は段階的に出します。

1. **②の解説**で r<sub>駅</sub>・r<sub>公園</sub> と「後 − 前」を一度だけ見せる（新しいことは教えず、
   いま描いた矢印に名前を付けるだけ）
2. **③④⑤**で使いながら慣れる
3. **「記号」ステップ**（②.5b の直後）で固める（式の順を問う選択問題＋成分の問題）
4. **第2弾シーン4**で、同じ形が相対速度にも使えることを確かめる

⑥とシーン4は `js/core/bridge.js` という同じ部品でできています。
**生徒が「第1弾のあの画面と同じ形だ」と気づけることがねらいなので、
片方だけ見た目を変えないでください。**

## ステップの並びと、話の区切り

```
導入 → ① 位置 → ② 変位 → ②.5a 置き直し → ②.5b 原点移動 → 記号 → ③ つなぐ
     → ④ 速度 → ⑤ 合成 → 振り返り
```

**「記号」は変位の話が続いているうちに置いています**（速度に入る前）。
変位の記号 r<sub>公園</sub> − r<sub>駅</sub> を扱うステップなので、速度のあとでは遅すぎます。

話が切り替わるところでは、**全画面の宣言**を出します。
`problems.js` の各ステップに `transition: { title, body, button }` を書けば、
どのステップでも出せます（`js/main.js` が共通で処理）。いま使っているのは3か所です。

| 場所 | 宣言 |
|---|---|
| ②.5b の前 | ここから、話が変わります（置き場所 → 基準そのもの） |
| ④ の前 | ここから、速度の話に入ります（1マスの意味が km → km/h） |
| ⑤ の前 | 動いているものが、2つ登場します |

### 飛ばさせたくない問題がある場合
`passLine` を満たすと「このステップは通過です／もう1問やる」のモーダルが出て、
残りを飛ばせてしまいます。**そのステップの要になる問題は、必ず最後まで解かせるよう
`passLine` を `{ correct: 問題数, of: 問題数 }` にしてください。**
①（基準を変えると矢印が変わる）と②（道筋が違っても同じ変位）がこれに当たります。

## 授業での操作

### キーボード
**N キーで「次へ」** に進めます。プロジェクタに映して進めるとき、マウスを触らずに操作できます。
押しているのは画面上のボタンそのものなので、**無効になっているボタンはキーでも押せません**
（例：第2弾のシーン1で、予測を描く前に N を押しても進みません）。
入力欄やテキストエリアに文字を打っているあいだは効きません。

### 作図の操作（タップ／ドラッグ）
スマホは **①始点をタップ → ②終点をタップ** が既定です。タブレット・PC は押したままドラッグ。

スマホでドラッグにしないのは、**指を離した瞬間に確定してしまい、始点が指で隠れたまま決まる**ためです。
タップなら1点目がスナップ後の位置に「ここから」の印で残り、違えば**同じ点をもう一度タップして打ち直せます**。
長押しメニューとも競合しません。順番に聞く形なので、「矢印は 前→後」という
このアプリのルールを操作そのものが教えることにもなります。

⚙から **タップ／ドラッグ／自動** を選べます（両アプリ共通、端末に保存）。

### 問題文と数値入力についての決めごと
- **問題文は省略しない。** 課題そのものなので、スマホでも折りたたまず全文を出します。
  そのぶん、**問題データ側の文を短く保ってください**（スマホで3行以内が目安）。
  文を長くすると、第2弾の二画面がスクロールなしで収まらなくなります。
- **符号は打たせない。** スマホの数字キーボードにはマイナスが無く、負の値を入力できません。
  向きは必ず**ボタンで選ばせ**、数値は大きさだけにしてください（⑥の成分、第2弾シーン4の速度とも同じ形）。

### 進捗バーからの移動
上部の進捗チップはタップで移動できます。ただし既定では **通過済みのステップに戻るだけ** です。
先へ飛べるようにすると、第2弾の「予測を描くまで再生できない」制約が意味を失うためです。

授業を途中から始めたいときは、⚙から **先生モード** をONにしてください。
どのステップにも移動できるようになります（点線のチップがまだ通っていないステップです）。
設定は端末に保存されるので、教員機で一度ONにすれば次回以降も有効です。
第1弾・第2弾で共通の設定です。

### アプリ間の移動
- 第1弾の最後に「第2弾：相対速度へ進む」ボタンが出ます
- ⚙メニューからは、どちらのアプリからでも相互に移動できます

## 相対速度だけを1コマで扱うとき

第2弾は第1弾の続きとして書かれていますが、**相対速度だけを単独で扱う授業**にも対応しています。

```
index.html?course=relative
```

このURLで開くと、第2弾に必要な前提だけを短く復習するコースになります（約7分）。

| | 内容 | なぜ必要か |
|---|---|---|
| ②.5b | 基準点を変えても変位は変わらない | 第2弾シーン0の宣言が、これを受けています |
| ④ | 速度ベクトル | 青い矢印と目盛の読み方 |
| ⑤ | 合成・差の作図 | 相対速度の作図そのもの |
| 記号 | 記号へ渡す | v<sub>AB</sub> ＝ v<sub>B</sub> − v<sub>A</sub> と同じ形をここで見ておく |

終わると、そのまま `relative.html` へ進むボタンが出ます。
**このURLをブックマークしておけば、1コマぶんの授業がひと続きで流れます。**
コース中は通常の進捗（「続きから」）を汚さないので、別の日に第1弾を通しでやっても影響しません。

第2弾側からも入れます。シーン0の「前提を復習してから（5分）」ボタン、または⚙メニューから。
復習コースの中身は `js/main.js` の `COURSES` で変えられます。

## スマホ対応

`js/core/layout.js` が画面幅で `phone` / `tablet` を判定します（手動切替も可）。
第2弾では、**スマホ（縦）で二画面を上下に並べ、両方が同時にスクロールなしで
見えること**を優先しています。高さが足りない場合は方眼の表示範囲を自動で狭めます。

## 動作環境

- モダンブラウザ（ES モジュール、SVG、Pointer Events）
- ビルド・依存パッケージなし
- 進捗は `localStorage` に保存（第1弾 `vec1.progress.v1` / 第2弾 `vec2.relative.v1`）
