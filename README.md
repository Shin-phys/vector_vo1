# ベクトル作図ステップ学習（物理基礎）

高校「物理基礎」の授業で使う、ベクトルの作図とその意味を段階的に学ぶ Web アプリです。
ビルド不要。静的ファイルをそのまま配信すれば動きます（ES モジュールを使うので
`file://` ではなく HTTP で開いてください）。

## 話の構成（トップページから選びます）

`index.html` を開くと**トップページ**が出て、どの話をやるか選びます。
各話は `index.html?course=<キー>` で直接開くこともできます（生徒に配るURLを分けたいとき）。

| キー | 話 | 内容 | 時間 |
|---|---|---|---|
| `ch1` | **第1話**　Sさんは、どこにいる？　どれだけ動いた？ | 位置・変位・速度の向き・自由／束縛・基準の取り替え・記号・速度 | 約40分（12問） |
| `ext` | **発展**　変位ベクトルを拡張すると見えてくること 〜斜方投射を題材に〜 | 速度ベクトルの先端どうしを結ぶ → 加速度 | 約10分 |
| `ch2` | **第2話**　ベクトルの足し算はどんな時にでてくるの？ | 変位をつなぐ・速度の合成 | 約11分 |
| — | **第3話**　相対速度 | `relative.html`（基準を動いている物体に取り替える） | 約15分 |

発展は第1話と第2話のあいだに置いていますが、**飛ばしても第2話は成立します**。

進捗は**話ごとに別々に**保存されます。第1話の途中で閉じても、次に第1話を開けば続きから再開でき、
第2話はそれとは無関係に最初から始まります。

> 以前「第2弾」と呼んでいた相対速度は、トップページ上では **第3話** と表示しています。
> ファイル名は `relative.html` のままです。

見た目・色の規約・操作感はすべての話で共通です。生徒が「別のアプリ」と感じないよう、
共通部品は `js/core/` に置いて両方から使っています。

## 第3話（相対速度）の設計で崩してはいけないところ

1. **`camera.js` の分離**
   `world.js` は「本当の運動」だけを持ちます。どの基準から見るかは `camera.js`
   だけが知っていて、`view.js` は world と camera を受け取って描くだけです。
   **観測者系のために別の world を作らないでください。**

2. **`gridOffset` による背景の追随**
   観測者系では `gridOffset = −(観測者の位置)` となり、方眼・道路のセンターライン・
   樹木・標識がすべて一緒に流れます。これがないと「球だけが違う速さで動く映像」に
   なってしまい、視点の乗り換えが伝わりません。

3. **シーン1の「描くまで再生できない」制約**
   予測を描くまで再生ボタンはグレーアウトします。ここを飛ばすと、このアプリは
   ただの綺麗な映像になります。

4. **シーン4の記号への橋渡し**
   矢印と式をタップで連動させ、最後に数値で解かせます。見て終わりにしないための
   シーンです。

`anchor`（観測者の出発点に原点を置く）も設計上の要です。これにより t=0 では
二画面が完全に一致し、時間が進むにつれて差が現れます。

## 授業での調整

### シーンを飛ばす
`js/relative/main.js` の `SCENE_PLAN` の該当行をコメントアウトします。
第1話・発展・第2話は `js/main.js` の `COURSES` が同じ役割です。

### 直線（1d）と平面（2d）の切り替え
教科書によって相対速度を直線上だけで扱う場合と平面まで扱う場合があります。

```js
// data/config.js
export const relativeConfig = { dimension: '1d' };  // "1d" | "2d"
```

既定は `1d`（道路を2台が走る横からの図）です。`2d` にすると俯瞰の図
（斜めに交差する2物体・川を渡る舟）に切り替わります。問題データは
`data/problems-relative.js` に両方そろえてあります。
授業中に切り替えたいときは、画面右上の⚙からも変更できます（最初からやり直しになります）。

### 速さや配置を変える
`data/problems-relative.js` の `bodies[].vel` は **方眼のマス／秒** です。
表示される速さは `|v| × unitScale`（既定 10）で `m/s`。
`duration` を変えるときは、物体と矢印の先端が画面からはみ出さないか確認してください。

## 記号への橋渡し

このアプリの背骨は、**同じ1つのルール**です。

> **移動前が bef、移動後が aft。矢印は bef → aft、式は aft − bef。**

| | 添字 | 式 | 読み |
|---|---|---|---|
| 変位（第1話⑥） | 駅 → 公園 | r<sub>aft</sub> − r<sub>bef</sub> | 駅を基準にすると、公園はどこか |
| 相対速度（第3話シーン4） | A → B | v<sub>B</sub> − v<sub>A</sub> | Aを基準にすると、Bはどう動くか |

矢印の向きと式の並び順が逆になるのが最大のつまずきどころです。

記号は段階的に出します。

1. **②の解説**で r<sub>駅</sub>・r<sub>公園</sub> と bef / aft を一度だけ見せる
2. **⑥**で、図を見ながら Δr → r<sub>bef</sub> → r<sub>aft</sub> → 式 の順に答えさせ、
   最後にきまりをまとめる（`step6.summary`）
3. **第3話シーン4**で、同じ形が相対速度にも使えることを確かめる

> **⑥は式を先に見せません。** 以前は `js/core/bridge.js` の式パネル（式を並べてタップで
> 図と連動させる枠）を使っていましたが、`Δr ＝ r_aft − r_bef` が画面に出ていると
> ④の答えそのものになるため、図と問いだけの画面に変えました。
> `bridge.js` は第3話シーン4が引き続き使っています（`plain: true` で図だけにもできます）。

## チップの番号

チップの番号は **`js/main.js` の `numberSteps()` が並び順から自動で振ります**。
データにもステップのファイルにも番号は書きません（`label` は名前だけ）。
導入・振り返りは番号をつけず、そのまま表示します。

| 話 | チップ |
|---|---|
| 第1話 | ①位置 / ②変位 / ③速度の向き / ④置き直す / ⑤基準 / ⑥記号 / ⑦速度 / 振り返り |
| 発展 | ①速度をつくる / ②Δv を見る / ③名前をつける |
| 第2話 | ①つなぐ / ②合成 / 振り返り |
| 第3話の復習コース | 確認 / ①基準 / ②記号 / ③速度 / ④合成 |

順番を入れ替えても番号は勝手に振り直されます。そのかわり、**本文中でステップを番号で
呼ばないでください**（「④で確かめたとおり」ではなく「置き直してよかった理由」のように、
内容で呼ぶ）。番号で呼ぶと、並べ替えたときに本文が嘘になります。

## 話ごとのステップの並び

`js/main.js` の `COURSES` に、話ごとのステップの並びが書いてあります。
**授業時間が足りないときは、該当する話の `steps` から1行コメントアウトするだけで飛ばせます。**

```js
const COURSES = {
  ch1: { label: '第1話',
         steps: ['step1','step2','stepv','step25a','step25b','step6','step4','reflection'], … },
  ext: { label: '発展', steps: ['ext1','ext2','ext3'], … },
  ch2: { label: '第2話', steps: ['step3','step5','reflection2'], … },
  relative: { label: '確認', steps: ['step25b','step6','step4','step5'], … }   // 相対速度の前提だけ復習
};
```

各話の `next` が「つぎの話へ進む」ボタンの行き先、`endText` / `endHint` が終わりの画面の文言です。
トップページに並ぶカード（見出し・説明・時間の目安・順番）は、同じファイルの `CHAPTERS` にあります。

**「記号」は変位の話が続いているうちに置いています**（速度に入る前）。
変位の記号 r<sub>公園</sub> − r<sub>駅</sub> を扱うステップなので、速度のあとでは遅すぎます。

話が切り替わるところでは、**全画面の宣言**を出します。
`problems.js` の各ステップに `transition: { title, body, button }` を書けば、
どのステップでも出せます（`js/main.js` が共通で処理）。いま使っているのは3か所です。

| 場所 | 宣言 |
|---|---|
| 「基準」の前 | ここから、話が変わります（置き場所 → 基準そのもの） |
| 「速度」の前 | ここから、速度の話に入ります（1マスの意味が km → km/h） |
| 「合成」の前 | 動いているものが、2つ登場します |

### 出した問題は全部やらせる

途中で切り上げる仕組みは置いていません。**ステップに並べた問題は、最後まで全部解かせます。**
「生徒を足止めしない」は問題ごとに担保していて、**3回まちがえると解説と答えを出して次へ通します**。

授業時間を削りたいときは、`data/problems.js` で
**その問題のかたまりごとコメントアウト**してください。

## 第1話の流れ（崩してはいけない順番）

```
①位置        冒頭で「この時間はSさんの位置と移動を矢印で表す」と宣言
             公園→駅（位置ベクトルとは何か）→ 基準を学校に替えると矢印が変わる
             → 公園→駅を消し、学校→公園を描いて「同じ基準点から2本」
②変位        Δr（駅→公園）→ 道筋がぐねぐねでも同じ
③速度の向き  タップで選ぶ → v ＝ Δr/Δt → ここまでの整理（4点）
④置き直す    自由／束縛を予想（採点しない）→ 動かす → もう一度たずねる
             →「変位も動かしてはいけないのでは？」で一度立ち止まる（`note`）
             → 課題1：2つの変位を等しくする（あり得る／あり得ないも採点しない）
⑤基準        なぜ動かしてよかったのか → O を動かす → 変化を表すベクトルは移動できる
⑥記号        Δr → r_bef → r_aft → 式 → 記号のきまり（⑦の前）
⑦速度        速度の矢印（km → km/h）→ 負の速度 → Δv（時間で割ると？）
振り返り
```

要になっているつながりが4つあります。**ここを入れ替えると授業が成立しません。**

1. **①は「基準を替える」を先に見せ、最後に同じ基準点から2本そろえること。**
   1問目の基準は**公園**、2問目で**学校**に替えます（地点＝駅は動かさない）。
   3問目で公園→駅を消し、学校→公園を描かせて、**学校から2本**そろえて終わります。
   この2本の先端を結ぶのが②の Δr で、⑤の「先端は動かない」も、⑥の `aft − bef` も、
   この2本に乗っています。**3問目では、2問目で描いた「学校→駅」を画面に残してください。**
2. **④→⑤のつなぎ。** ⑤の冒頭は「なぜ Δr は動かしてよかったのか。基準そのものを動かして
   確かめよう」と、④の答え合わせとして入ります（`step25b.transition`）。
3. **⑥では式を先に見せない。** 図と「いま答える問い」だけを置きます。式を並べる枠も、
   タップで光る仕掛けも持ちません（`Δr ＝ r_aft − r_bef` が答えそのものになるため）。
   きまりは⑥の最後に `step6.summary` として出し、そのまま⑦へ渡します。
4. **⑦の最後の Δv では「加速度」と名乗らない。** 「時間で割ると何になるか」で止め、
   発展ページに渡します。ここで名前を出すと発展の山場が消えます。

④の `note`（「この点からその点まで変位した、という事実が重要なのだから、こちらも
動かしてはいけないのでは？」）は**わざと潰さずに置いています**。教室で必ず出る反論で、
しかも正しい直観です。そこで答えを言わず「では、次の例ではどうだろう」と課題1へ渡します。

**予想は採点しません。** ④には予想が2つ（自由／束縛、あり得る／あり得ない）あり、
どちらもどれを選んでも「では、実際にやってみよう」で先へ進みます。確かめたあとに
採点ありの問いを置いています。

「ここまでの整理」は `problems.stepv.summary`、⑤のポイントは `problems.step25b.summary`、
⑥の記号のきまりは `problems.step6.summary` です。

## 発展（斜方投射）の設計

数字は偶然ではありません。**Δv がぴったり同じ矢印になる**ように置いてあります。

| | 座標 | |
|---|---|---|
| P₀ → P₁ | (1,1) → (3,5) | v₀₁ = (2, 4) |
| P₁ → P₂ | (3,5) → (5,7) | v₁₂ = (2, 2) |
| P₂ → P₃ | (5,7) → (7,7) | v₂₃ = (2, 0) |

x 成分はずっと 2、y 成分だけが 4 → 2 → 0 → −2。よって **Δv は3本とも (0, −2)**。
頂点（P₂〜P₃）をまたいでも変わらないので、「**上りでも下りでも加速度は同じ**」が絵で見えます。ここが崩れると発展の山場が消えるので、**座標を変えるときは
「x 成分を一定に、y 成分を等差に」を守ってください。**

始点をそろえる点 A は (2, 1)。そろえると 3 本の先端が (4,5) (4,3) (4,1) に一直線に並びます。
`ext2` の2問目以降は、この「そろえた後」の座標を静的に書いてあります（A・T1・T2・T3）。
A や P を動かした場合は、そちらの座標も直してください。

位置ベクトルは最初から描いてあります（生徒には描かせません）。ただし
**基準点 O はどの画面でもドラッグできます** — 第1話でやった「O を動かしても点と点のあいだの
矢印は変わらない」を、ここでもう一度確かめられるようにするためです。

## 成分の表記（±x / ±y）

**東西南北は使いません。** 向きも成分も、すべて `x` と `y` の符号で書きます。

| | 書き方 |
|---|---|
| 数値表示 | `x +3　y −2` |
| 括弧書き（`show: 'components'`） | `(+3, −2)` |
| 0 | 符号をつけず `0` |
| マイナス | 見やすい `−`（U+2212）を使う |

**記号は斜体（イタリック）で組みます。** 物理量の記号を斜体にするのは ISO 80000-2 の
決まりで、日本の教科書もセリフ体のイタリックです。本文の `.vec` と図の中の記号（`.sym-main`）に
斜体セリフを当てています。**Δ と、bef・aft・駅 のような説明的な添字は立体のまま**です
（これも同じ決まり）。

図の中の記号は、文字列に矢印を埋め込まず `label` / `labelSub` / `vec: true` で組みます。

```js
{ id: 'vbef', from: 'A', to: 'Tb', style: 'velocity',
  label: 'v', labelSub: 'bef', labelTail: ' ＝ +3', vec: true }
```

方眼の外側に **+x（右向き）** と **+y（上向き）** の矢印を常時表示しています
（`GridCanvas.drawAxisHints`）。基準点は問題によって動くので、これは座標軸ではなく
**向きの目印**です。符号を読ませる以上、どちらが正かは常に画面に出ている必要があります。

問題文を書くときも `+x に 3`、`y に −2` の形に揃えてください。
方角に言い換えると、生徒は「西ってどっち」でつまずきます。相対速度（第3話）の
`directionWord()` も同じ表記で返します。

## 文言のきまり

- **敬体は使わない。** 指示は「〜しよう」、問いは「〜だろうか」、説明は言い切り。
- **一文を短く。** 同じことを言い直さない。解説は2段落まで。
- **ベクトルはベクトル表記。** 本文は `<span class="vec">r</span>`、図のラベルは合成矢印（`r` + U+20D7）。
- **割り算は分数で。** `v ＝ Δr ÷ Δt` ではなく `.frac` で分子・分母に組む。
- **果たせない予告を書かない。** 「この先でわかります」は、その先が本当にあるときだけ。

`draw-multi` の書き方：

```js
{
  id: 'ext1-v', type: 'draw-multi', style: 'velocity',
  targets: [
    { name: 'v₀₁', label: 'v₀₁', answer: { from: {x:0,y:1}, to: {x:2,y:5} } },
    …
  ],
  progressText: 'あと {n} 本。順番はどれからでもよい。',
  doneText: '4本そろった。'
}
```

残っている的のどれかに当たれば受け付けるので、**描く順番は問いません**。
全部描くまで「次へ」は押せません。

## 新しい問題を足すときの部品

`data/problems.js` に宣言を足すだけで使えるものです。

### 問題の型（`type`）

| `type` | 内容 |
|---|---|
| `draw-vector` | 矢印を1本描く |
| `choice` | 選択肢から選ぶ（`scene:` を書くと選んでいるあいだも図が残ります） |
| `explore-drag` | 動かして観察する（`requirement` を満たすと通過） |
| `free-place` | 点や矢印を配置して `conditions` を満たす |
| `slider-explore` | スライダーで値の変化を見る |
| `tap-select` | **画面の矢印をタップして選ぶ**（「速度と同じ向きの矢印はどれ？」） |
| `draw-multi` | **1画面で複数の矢印を描き切る**（発展の v 4本、Δv 3本） |
| `free-text` | 自由記述（コピーして提出） |
| `text-answer` | **ことばを入力して答える**（発展の「漢字三文字」） |
| `note` | **問いではなく、途中に挟む短いガイド**（`body` を出して「次へ」だけ。`scene:` も書けます） |

`text-answer` の書き方：

```js
{
  id: 'ext3-name', type: 'text-answer',
  prompt: 'Δv ÷ Δt（1秒あたりの速度の変化）を表す量には、名前がついています。',
  question: '漢字三文字で入力しよう。',
  placeholder: '漢字三文字',
  accept: ['加速度'],                       // 正解（複数書けます）
  nearMiss: [                               // 惜しい答えに個別の返しをする
    { text: '重力', feedback: '向きは合っています。でも重力は「力」の名前です。…' }
  ],
  wrongText: 'どれにも当てはまらないときの返し',
  explanation: '3回まちがえたときの解説'
}
```

全角・半角・空白のゆれは吸収してから比べます。3回まちがえると正解を見せて次へ通します。

### 配置の条件（`free-place` の `conditions`）

| `kind` | 判定すること | `of` に書くもの |
|---|---|---|
| `vectorsEqual` | 2つの変位が等しい | 点のペア2組 |
| `pointsApart` | 2点が離れている（`minDistance`） | 点のキー2つ |
| `vectorsConnected` | 2本目の始点が1本目の終点に重なった | 矢印のid 2つ |
| `vectorsShareStart` | **挙げた矢印の始点がすべて同じ点にそろった** | 矢印のid（`at:` に点のキーを書くとその点に限定） |

### 記号の書き方

出発を **bef**、到着を **aft** で統一しています。

- 矢印は **bef → aft**、式は **aft − bef**
- Δr = r<sub>aft</sub> − r<sub>bef</sub>、Δv = v<sub>aft</sub> − v<sub>bef</sub>

新しい問題の解説文を書くときも、この2語に揃えてください。生徒がこの授業で覚える語です。

## 授業での操作

### キーボード
**N キーで「次へ」** に進めます。プロジェクタに映して進めるとき、マウスを触らずに操作できます。
押しているのは画面上のボタンそのものなので、**無効になっているボタンはキーでも押せません**
（例：第3話のシーン1で、予測を描く前に N を押しても進みません）。
入力欄やテキストエリアに文字を打っているあいだは効きません。

### 作図の操作（ドラッグ）
**すべての端末で「押したままドラッグ」が既定です。** 矢印を引くという動作そのものが
学習内容なので、そこは崩しません。

スマホでドラッグが難しい理由（指が太い・先端が指で隠れる）には、
**画面に見えている点への甘い吸着**で対処しています。

- 基準点・目印・シーンに出ている点・矢印の両端が「吸着先」になります
- 指がその近く（`layoutProfiles.<profile>.snapRadius`、スマホは 46px）に来れば、そこへ吸いつきます
- 吸着先が近くになければ、これまでどおり格子点へ丸めます
- マウスは正確なので、半径を 0.6 倍にして効かせすぎないようにしています

**答えの端点は吸着先に入れていません。** 入れると当てられてしまうためで、
吸着するのはあくまで「生徒に見えている点」だけです。

`js/main.js` の `draw-vector` ハンドラが `item.origin` / `item.landmarks` / `item.scene` から
吸着先を集めて `DrawTool` に渡します。新しい問題を足しても自動で効きます。

⚙から **タップ／ドラッグ／自動** を選べます（両アプリ共通、端末に保存）。
タップ方式（①始点→②終点）は、指の震えでドラッグが途切れてしまう生徒のための逃げ道として
残してあります。

### 問題文と数値入力についての決めごと
- **問題文は省略しない。** 課題そのものなので、スマホでも折りたたまず全文を出します。
  そのぶん、**問題データ側の文を短く保ってください**（スマホで3行以内が目安）。
  文を長くすると、第3話の二画面がスクロールなしで収まらなくなります。
- **符号は打たせない。** スマホの数字キーボードにはマイナスが無く、負の値を入力できません。
  向きは必ず**ボタンで選ばせ**、数値は大きさだけにしてください（⑥の成分、第3話シーン4の速度とも同じ形）。

### 進捗バーからの移動
上部の進捗チップはタップで移動できます。ただし既定では **通過済みのステップに戻るだけ** です。
先へ飛べるようにすると、第3話の「予測を描くまで再生できない」制約が意味を失うためです。

授業を途中から始めたいときは、⚙から **先生モード** をONにしてください。
どのステップにも移動できるようになります（点線のチップがまだ通っていないステップです）。
設定は端末に保存されるので、教員機で一度ONにすれば次回以降も有効です。
すべての話で共通の設定です。

### 話のあいだの移動
- **画面左上の 🏠 でいつでもトップ（話の選択）へ戻れます**（第3話の画面にもあります）
- 各話の最後に「つぎの話へ進む」「トップへもどる」「この話をもう一度」の3つが出ます
- ⚙メニューからは「第3話（相対速度）へ」「相対速度の前提だけ復習する」に移動できます

⚙メニューは**スマホではボタンを縦に積みます**（横並びだと画面からはみ出して押せませんでした）。

## 相対速度だけを1コマで扱うとき

第3話は第1話の続きとして書かれていますが、**相対速度だけを単独で扱う授業**にも対応しています。

```
index.html?course=relative
```

このURLで開くと、第3話に必要な前提だけを短く復習するコースになります（約7分）。

| | 内容 | なぜ必要か |
|---|---|---|
| 基準 | 基準点を変えても変位は変わらない | 第3話シーン0の宣言が、これを受けています |
| 速度 | 速度ベクトル | 青い矢印と目盛の読み方 |
| 合成 | 合成・差の作図 | 相対速度の作図そのもの |
| 記号 | 記号へ渡す | v<sub>AB</sub> ＝ v<sub>B</sub> − v<sub>A</sub> と同じ形をここで見ておく |

終わると、そのまま `relative.html` へ進むボタンが出ます。
**このURLをブックマークしておけば、1コマぶんの授業がひと続きで流れます。**
このコースは `relative` という別キーで進捗を持つので、別の日に第1話を通しでやっても影響しません。

第3話側からも入れます。シーン0の「前提を復習してから（5分）」ボタン、または⚙メニューから。
復習コースの中身は `js/main.js` の `COURSES` で変えられます。

## スマホ対応

`js/core/layout.js` が画面幅で `phone` / `tablet` を判定します（手動切替も可）。
第3話では、**スマホ（縦）で二画面を上下に並べ、両方が同時にスクロールなしで
見えること**を優先しています。高さが足りない場合は方眼の表示範囲を自動で狭めます。
